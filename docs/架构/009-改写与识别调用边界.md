# 009 改写与识别调用边界

**状态：已采纳，2026-09-28。** 问题改写与意图识别由独立应用模块完成，调用 AgentScope 的模型接口，不注册成 Master 的工具或 Skill。这样可以在业务工具暴露前解析并校验意图，改写也能使用跨 Agent 的业务历史，而不是某个 Agent 的私有记忆。它们可独立测试，不需要构造 Master。

## 调用顺序

| 情况 | 目标顺序 | 当前状态 |
| --- | --- | --- |
| 普通新请求 | 认证并保存用户消息 → 原句快速识别 → 命中后把结果交给 Master | 快速层由 012–015 实现，HTTP 编排由 017 接入。 |
| 快速层未命中 | 鉴权读取历史 → 改写一次 → 结果完整后进行完整识别 → Master | 本次实现上下文构造、独立改写与 LLM 识别；完整流水线尚未接入。 |
| 缺少指代上下文 | 改写返回 `rewritten_question=null` 和缺项，调用方先处理澄清 | 不把未完成结果当作可执行问题；自动交互流程仍属后续编号。 |
| 模型输出非法或调用失败 | 明确失败，停止当前预处理 | 不修复重试，不把错误转换成已识别意图或原始模型文本。 |

`IntentRecognizer.recognize()` 是唯一意图判定入口，当前内部只有单次 LLM 路径。012 起在同一模块内加入快速层及是否进入 LLM 的控制，外层流水线只管理顺序，不复制分类提示词或另造一套目标 Agent 映射。高置信直跳当前仍未启用，先保持 Master 路径。

一次 `rewrite()` 或 `recognize()` 最多一次模型生成；外层若依次调用两者，就是两个不同步骤、合计最多两次生成。无需改写的独立问题在一次判定中输出原句，调用方直接使用它；无历史并不自动证明无需改写。快速命中时的零改写调用属于后续快速层与编排职责。

## 模块职责

| 模块 | 负责什么 |
| --- | --- |
| [intent/models.py](../../src/gogo_agent/intent/models.py) | 008 的输入输出契约，以及历史片段、日期和改写上下文；不决定身份或执行角色。 |
| [intent/context.py](../../src/gogo_agent/intent/context.py) | 经 `ChatHistoryService` 校验所有权后取最近历史，分离本轮问题并裁剪历史文本。 |
| [intent/service.py](../../src/gogo_agent/intent/service.py) | `QueryRewriter.rewrite` 与 `IntentRecognizer.recognize`；共用一次模型调用和 JSON 校验实现。 |
| [chat/service.py](../../src/gogo_agent/chat/service.py) | 当前用户与会话的归属校验、业务消息存取；可信用户 ID 由应用调用方传入。 |
| 后续应用流水线与 Master | 前者决定步骤顺序，后者按有效意图协调已实现的业务角色；均不重复进行隐藏的意图识别。 |

模型接收的历史以 JSON 数据放在一条 `UserMsg` 中；其中的业务 `system` 标签不会被转成有更高优先级的模型 `SystemMsg`。模型输出里的 `target_agent`、身份和未定义字段仍由 008 契约拒绝。

## 取舍及依据

把改写/识别放进 Master 的推理或 Skill 会让调用次数、先后顺序和重试取决于工具循环，还会混入 Master 的状态。独立模块需要应用明确构造上下文和处理失败，但这些行为可以通过固定模型替身验收。

本次并未把模块挂到 HTTP 对话入口，也没有新增工具权限、业务角色或 AgentState。单次调用参数、上下文窗口、实际错误出口和验收方法见 [010–011 实现说明](../契约样例/010-011-单次调用与上下文.md)。
