# 阶段 C：主 Agent、模型配置与身份边界（023–028）

[学习路线首页](README.md) · [阶段 B](阶段B-006-022.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：一个 AgentScope 2.x 主 Agent、至少一个只读子 Agent、统一模型配置和可信身份传递。继续使用隔离数据和可替换的模型响应。

### [ ] 023 主智能体功能与开发

- **理解**：看 Java `MasterAgent` 真正注册的管理、规划、信息、预订四个子 Agent，以及用户交互工具；它没有 README 某些版本写的 `InfoQueryTools`。学习 AgentScope 2.x `Agent.reply()`/`reply_stream()`、工具调用和权限事件。
- **动手**：建立主 Agent 的提示词、模型和最小 Toolkit，先接入“信息查询”假子 Agent，再按阶段加入其余三个；先用应用层明确传 `RequestContext`，再确定是否用框架团队能力。保持唯一的主协调入口。
- **验收**：一个查询从 HTTP/CLI 经意图流水线到主 Agent，再到只读子 Agent，最后回到用户；工具调用有可见记录，未注册的工具不能被调用。

### [ ] 024 Agent 关键配置

- **理解**：分清系统提示词、模型选择、上下文长度、推理轮数、工具并行、超时、权限与中断；AgentScope 2.x 配置以锁定版本 API 为准。
- **动手**：建立集中配置和环境变量清单，为主 Agent 设置合理的轮次、超时、工具权限及错误出口；用配置而非散落常量控制。
- **验收**：缺模型配置时启动失败且不泄密；工具超时、模型错误、轮次耗尽各有可观察结果；更改配置无需修改业务规则。

### [ ] 025 各 Agent 配置对比

- **理解**：不同 Agent 有不同工具与状态，不应全量共享同一 Toolkit 或提示词。
- **动手**：原 025 正文仍是草稿，配置矩阵要从源码建立：名称、模型、提示词、工具、状态范围、输出 schema、写入权限、超时；与 Java 的 6 个 ReAct Agent 和轻量服务逐项对照。
- **验收**：矩阵能解释为什么审核 Agent 看得到计划但下不了订单，信息 Agent 查得到知识却改不了差旅单。

### [ ] 026 模型分工

- **理解**：看 Java 当前 `ModelConfig` 的快模型、主模型与 OpenAI 兼容网关用途；原 026 文章中的模型名称已有漂移，以代码为准。把服务地址、密钥和模型名分开配置。
- **动手**：实现统一模型工厂或少量配置函数；分别让意图兜底、主 Agent 使用目标模型，记录一次调用的模型名、耗时与 token 使用量（可用时）。
- **验收**：测试可以替换模型客户端而不访问网络；密钥不进入日志；模型切换不会改变用户身份或业务仓储入口。

### [ ] 027 快速路由到上次子 Agent

- **理解**：Java 的“续上次 Agent”来自持久化 active agent 和 `ContinuationSignals.ALL` 精确命中的信号，MasterAgent 本身不覆盖活跃子 Agent；这和第 019 项被注释的高置信直跳是两回事。
- **动手**：在会话状态保存 active agent 名称；只对已认证的同一 session 和有效续聊信号走续跑路径，其他输入走完整意图流水线。
- **验收**：连续追问进入原 Agent；换话题、状态缺失、状态过期、跨用户请求都不错误续跑。

### [ ] 028 防止模型传错 `userId`

- **理解**：模型可生成任意工具参数，`userId` 是权限边界而非提示词问题。
- **动手**：所有用户级工具在服务层从 `RequestContext` 注入身份，移除或忽略模型提供的 `userId`；查询和写入仓储都附所有权约束。
- **验收**：构造模型传入他人 `userId`、篡改 session ID、跨用户计划引用的负例，均无法读取或修改他人数据。

## 阶段验收

能演示“认证用户 → 意图识别 → MasterAgent → 只读子 Agent → 回复”与“同会话续跑”两条链路。跨用户负例通过后进入[阶段 D](阶段D-029-041.md)。
