# 阶段 F：预订 Agent、幂等与工具可靠性（061–067）

[学习路线首页](README.md) · [阶段 E](阶段E-042-060.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：在模拟供应商环境下完成“审核通过 → 用户确认 → 下单/取消 → 本地记录”，并验证失败与重试不会重复写入。真实订单只在单独的受控集成阶段验证。

### [ ] 061 为什么独立 BookingAgent

- **理解**：规划 Agent 负责候选与权衡，BookingAgent 负责有副作用的预订；两者所需工具、权限和用户确认不同。
- **动手**：对照 `MasterAgent` 的注册关系和 `BookingAgent` 实现，写输入/输出/确认/失败责任表；把“计划已审核”作为预订前置条件。
- **验收**：规划完成不自动下单；预订 Agent 无法修改审核结论；系统中只有一条权威下单路径。

### [ ] 062 行程预订智能体

- **理解**：一笔预订有用户确认、供应商请求、未知结果、成功、取消等状态；模型的“已下单”文字不是订单事实。
- **动手**：建立 BookingAgent 和模拟供应商，先执行固定 `plan_id` 的确认后下单；保存请求 ID、供应商单号与最终状态。审批/预订权限由服务端校验。
- **验收**：未确认、计划不属于用户、审核未通过均不能下单；成功时本地记录与模拟供应商一致；超时未知时不会宣称成功。

### [ ] 063 下单用 Skill、取消用工具

- **理解**：区分源项目下单 CLI/Skill 与取消工具的真实能力和调用副作用，不为了形式把两条路径做成两个订单系统。
- **动手**：分别包装源端实际使用的下单与取消入口，统一通过同一个预订服务处理权限、幂等、状态与审计；不把 shell 字符串直接交给模型执行。
- **验收**：一笔订单无论经哪个外部入口变化，本地只存在一条记录；取消非本人/不存在订单失败。

### [ ] 064 预订业务数据模型

- **理解**：看 `booking_record` 的关联订单、用户、品类、供应商单号、金额、状态与时间；明确哪些字段是唯一标识。
- **动手**：定义 Python 模型、约束和仓储事务；为请求幂等键、供应商请求 ID、回调事件 ID 建唯一性/去重规则。
- **验收**：重复响应/重复回调不会生成两条订单；失败与取消不会丢掉原请求证据；金额和币种被正确保存。

### [ ] 065 Skill 还是 SubAgent

- **理解**：Skill 提供具体外部操作说明或工具，SubAgent 负责较长的独立决策；一个能力不应同时在两处成为权威实现。
- **动手**：给每个旅行能力填“任务边界、状态、是否需模型推理、工具权限、副作用”表；确认搜索、方案计算、审核、下单各自归属。
- **验收**：Master/规划/预订的 Toolkit 没有重复可写工具；同一用户动作只进入一个执行入口。

### [ ] 066 工具并行与失败重试

- **理解**：独立只读搜索可并行；下单和取消不能仅凭超时无脑重试，需要幂等或先查供应商状态。
- **动手**：用 `asyncio` 并发模拟多供应商搜索，限定并发数与超时；为可重试错误、不可重试错误及未知写入结果分别定义策略。
- **验收**：并发只读调用较串行缩短耗时且结果不串用户；模拟“已成功但响应丢失”时重试不会多下一单。

### [ ] 067 工具级熔断

- **理解**：连续供应商失败时继续调用会扩大故障；熔断有关闭、打开、半开探测和恢复状态。
- **动手**：对实际不稳定的外部工具实现或复用熔断状态，记录失败阈值、冷却时间和用户可见错误；不要给所有纯函数套熔断。
- **验收**：连续失败后停止外呼；冷却后只进行受控探测，成功恢复、失败继续打开；其他工具仍可用。

## 阶段验收

模拟一笔成功预订、一笔响应丢失、一笔取消和一笔跨用户越权请求；核对外部调用次数、状态与审计。通过后进入[阶段 G](阶段G-068-085.md)。
