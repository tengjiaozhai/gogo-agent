# 阶段 D：差旅管理 Agent 与确定性工具（029–041）

[学习路线首页](README.md) · [阶段 C](阶段C-023-028.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：差旅单领域模型、受控的读写工具、审批状态机、政策检索与问题推荐。先把业务函数写对，再暴露给 AgentScope Toolkit；不让模型直接操作数据库。

### [ ] 029 行程管理智能体

- **理解**：看 Java `ItineraryManageAgent` 的提示词、工具和调用方；区分差旅单管理与行程规划、预订。
- **动手**：用 AgentScope 2.x 建管理 Agent，只注册此角色所需的政策、联系人、差旅单工具；在 MasterAgent 里接入它。
- **验收**：“查我的差旅单”到管理 Agent；“设计路线”到规划职责；管理 Agent 没有供应商下单权限。

### [ ] 030 行程管理业务数据模型

- **理解**：逐表看 `schema.sql` 中 `travel_order`、`approval_record`、`user_profile` 等字段、索引、状态和时间/金额语义。
- **动手**：定义 Python 领域模型和 Pydantic 请求/响应，写状态转换表；建立只用于测试的建表/迁移脚本。数据访问通过仓储，不能让工具拼接任意 SQL。
- **验收**：合法、缺字段、非法日期、无效状态和重复状态转换都有明确结果；可将一个 Java 测试样例映射成同义 Python 对象。

### [ ] 031 好工具的定义

- **理解**：学习 AgentScope 2.x `FunctionTool`/`ToolBase` 的输入 schema、工具说明、调用结果和权限事件；区分只读、写入和外部副作用。
- **动手**：先做 `get_travel_order` 只读工具，定义参数、返回值、错误码、身份注入、超时与日志字段；用假仓储测试后再放入 Toolkit。
- **验收**：合法订单可读，不存在/非本人订单失败；模型传错参数不会产生写入；工具的输出可被后续 Agent 稳定解析。

### [ ] 032 差旅政策工具

- **理解**：政策的结构化规则查询与文档知识库检索用途不同；识别适用城市、职级、费用上限及生效时间。
- **动手**：移植 `PolicyTools` 对应的精确查询与合规检查为纯业务函数，再包装工具；用测试数据覆盖边界值。
- **验收**：在上限、刚超上限、无适用规则、已过期规则等场景给出确定结果并标明依据。

### [ ] 033 用户联系信息工具

- **理解**：用户资料是认证用户拥有的业务数据，读写权限与模型文本无关。
- **动手**：移植资料读取和受控更新，限制可写字段；所有仓储查询按认证用户过滤；不要把联系方式完整写进日志。
- **验收**：本人可读写允许字段；模型传入他人 ID 或未知字段失败；日志与工具错误不泄露完整个人资料。

### [ ] 034 差旅政策知识库

- **理解**：看 Java 政策 DOCX 如何读取、切片、向量化；政策问答必须能追溯文档版本，不能把相似度当成合规结论。
- **动手**：写离线导入脚本与只读检索工具，保存文档来源、版本和片段；先用少量脱敏政策样例，再接真实资料。
- **验收**：已知问题能取回正确片段；文档更新后索引可重建；未命中时明确说明无依据，不伪造政策。

### [ ] 035 差旅单管理工具

- **理解**：梳理创建、修改、提交审批、查询、取消各状态的前置条件、事务和副作用。
- **动手**：按 Java `TravelOrder` 服务写业务函数与仓储事务；把写操作包装为需用户确认的工具，保存请求幂等键和审计记录。
- **验收**：合法状态转移成功；重复提交、已审批后修改、跨用户取消失败；数据库状态与返回值一致。

### [ ] 036 行程冲突检测工具

- **理解**：时间重叠之外还要检查跨城衔接、交通耗时与时间边界；测试不依赖大模型。
- **动手**：移植 `TravelOrderConflictTools` 与城市间通行时间逻辑，固定时区、日期闭开区间和冲突严重程度。
- **验收**：重叠、不重叠、跨城来不及、恰好接续、缺少交通数据分别得到稳定结果，并能解释触发规则。

### [ ] 037 预订管理工具

- **理解**：先区分内部 `booking_record` 的查询/取消与外部供应商真实下单；本节只确立管理契约，不提前开放真实支付或下单。
- **动手**：实现本人预订记录查询、按状态筛选、模拟取消请求的服务函数和工具适配；对外部动作预留确认与幂等所需字段。
- **验收**：用户只能查看自己的记录；重复取消不会出现两个相反状态；真实供应商调用仍由后续 061–064 步验收。

### [ ] 038 行程审批及管理

- **理解**：读 `AdminApprovalController`、`ApprovalCallbackController` 和审批服务，画审批状态机；Java 回调控制器标注“待完善”，要核对来源认证是否在外围。
- **动手**：实现管理员审批的角色校验、审批记录和差旅单状态原子更新；模拟钉钉回调时先验证来源签名/密钥策略，再接受事件。未确认可信来源前只保留禁用/模拟入口。
- **验收**：管理员可审批，普通用户不可审批；重复/过期回调幂等；伪造回调不能改变差旅单状态。

### [ ] 039 工具缓存

- **理解**：缓存适用于可重复的只读查询；用户资料、政策或预订状态都需要清楚的隔离和失效规则。
- **动手**：从实际重复调用数据选择一个只读工具做缓存，键包含用户或租户、参数和数据版本，设 TTL 与更新后失效。
- **验收**：重复同参命中缓存；用户 A 与 B 不共享私有数据；原始记录变更后不会读到过期决策值。

### [ ] 040 基于回答的问题推荐

- **理解**：Java `QuestionRecommendationService` 是主答复之后的轻量模型调用，不是 ReAct Agent；推荐失败不能覆盖答案。
- **动手**：在答复完成后生成少量下一步建议；用固定模型响应测试解析、去重和失败降级。
- **验收**：主答复始终先完成；建议内容与用户当前场景相关；模型错误时主流程成功且没有空白错误卡片。

### [ ] 041 是否关闭深度思考

- **理解**：模型“深度思考”开关会影响延迟、输出与成本；它是模型参数，不是业务正确性的替代品。
- **动手**：核对 Java 实际模型参数，在相同问题集下比较开启/关闭的延迟、结构化输出有效率和工具误调用；只为确有收益的模型设置。
- **验收**：有原始测量和最终配置理由；开关改变不导致政策或订单规则交给模型自行判断。

## 阶段验收

用隔离数据库完成差旅单申请、查询、修改、提交审批和管理员审批；政策、联系人和冲突检测均有正反例。没有真实供应商下单。通过后进入[阶段 E](阶段E-042-060.md)。
