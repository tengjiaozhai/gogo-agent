# 阶段 A：从空项目到可保存对话（001–005）

[学习路线首页](README.md) · [长期路线图](../AgentScope-Python-迁移路线图.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：可运行的 Python 包、锁定依赖、最小 Agent + 工具、HTTP 服务、登录和会话/消息存取。建议先完成首页的 000 小练习。此阶段所有业务数据使用隔离测试库。

### [ ] 001 项目如何启动与快速开始

- **理解**：看 Java `GogoTravelApplication`、`pom.xml`、`application.yml` 的启动依赖；区分 Python 运行时、包、虚拟环境、模型提供商凭证。阅读锁定版本的 AgentScope 2.x `Agent`、`Toolkit`、`FunctionTool` 最小例子。
- **动手**：把示例 `main.py` 变成最小 `gogo_agent` Python 包；在 `pyproject.toml` 锁定经过实际安装验证的 Python/AgentScope 版本。写 `cli.py`：建立一个只会调用无副作用 `get_current_date()` 工具的 Agent，用现有模型网关的测试凭证运行一次；另提供 `--help`/健康检查和 `.env.example`（只有变量名，没有密钥）。
- **验收**：新环境按 README 一条命令安装并启动；能打印 AgentScope 版本、完成一次模型回答和一次工具调用；未配置模型凭证时明确报错；`pytest` 的纯工具测试不依赖真实模型。若 3.14 与依赖不兼容，先试已支持版本并修改约束，不在未验证前做大量开发。

### [ ] 002 项目功能介绍与演示

- **理解**：原 002 正文仅提示观看视频，因此沿 Java `LoginController`、`ChatController`、`MyTravelController`、`AdminApprovalController` 手动走一次用户旅程；标记真实实现、README 宣称和待办之间的区别。
- **动手**：建立 `docs/契约样例/`（或等价记录），按“登录→对话→差旅单→规划→审核→预订”保存脱敏输入、HTTP 状态、响应/SSE 事件、数据库副作用。无法启动 Java 时先从控制器和测试摘出**静态契约**，标注未做运行验证。
- **验收**：每条样例都注明来源、运行条件及外部写入风险；报销 Agent `build()` 返回 `null`、A2A 未实现和单意图直跳未启用的事实不被写成已完成能力。

### [ ] 003 整体架构与核心功能

- **理解**：从 `ChatController → ChatAgentExecutor → AgentPipelineService → MasterAgent/子 Agent` 追一次请求；区分接口、编排、Agent、确定性业务服务、仓储与外部适配器。
- **动手**：画一页 Python 调用图并建立 Java→Python 入口表，列出 `/api/auth`、`/api/chat`、`/api/my-travel`、`/api/preferences`、`/api/admin`、回调接口和事件名称。做一个小型对照：自建薄 FastAPI 兼容层与 AgentScope 自带 Agent Service，检查哪个更容易保持现有前端协议和登录方式，然后选一个权威 HTTP 入口。按需要创建 `api/`、`agent/`、`business/`、`persistence/` 模块，不提前建空类。
- **验收**：任选一个登录后发聊天消息的场景，能在图上指出每层处理者、身份来源、状态写入点和错误出口；决定保留哪种 HTTP 入口并说明理由。AgentScope 自带服务示例的 `X-User-ID` 占位身份不能充当生产鉴权。

### [ ] 004 登录体系

- **理解**：读 Java `AuthService`、`LoginController` 与 `user_account` 表，理解密码验证、token、当前用户上下文、401/403 的区别；先核对原项目对 token 的真实生命周期。Java 当前有明文密码比较，不能不加判断地照搬。
- **动手**：建立最小账户仓储和登录/退出/用户信息接口；服务端从已验证 token 获取 `user_id`，不从请求体或模型输出取。为旧账号密码数据写清哈希迁移方案并在隔离数据上验证；测试合法、错误密码、过期/伪造 token、退出后的访问。不要复制 Java 配置里的任何密钥值。
- **验收**：两用户分别登录并访问自己的信息；无 token 与伪造 token 失败；用户 A 不能用用户 B 的 ID 读取数据；前端现有 `Authorization` 头格式有契约记录。

### [ ] 005 会话与消息持久化

- **理解**：区分 `chat_conversation`、`chat_message` 业务历史与 AgentScope Java `agentscope_session` 状态；理解一次请求结束、进程重启和跨用户读取时各自应保留什么。
- **动手**：实现会话创建/查询、消息保存/查询、标题更新的 Python 仓储和 HTTP 接口；为 AgentScope 2.x 的 Agent 状态单独选择持久化方式，不直接读取 Java 的序列化字节，也不照搬 Java 已废弃的“影子历史”路径。写入用户消息、Agent 回复与会话所有者时使用同一可信身份。先支持简单文本对话，挂起/恢复细节在 092/097 补齐。
- **验收**：用户 A 创建会话、发两轮消息、重启服务后历史仍在且顺序正确；用户 B 查同一 session 返回拒绝或不存在；业务消息与 Agent 内部状态的存储位置有明确说明。
