### [x] 004 登录体系 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/004_✅登录体系开发及介绍.md>)

- **理解**：读 Java `AuthService`、`LoginController` 与 `user_account` 表，理解密码验证、token、当前用户上下文、401/403 的区别；先核对原项目对 token 的真实生命周期。Java 当前有明文密码比较，不能不加判断地照搬。
- **动手**：建立最小账户仓储和登录/退出/用户信息接口；服务端从已验证 token 获取 `user_id`，不从请求体或模型输出取。为旧账号密码数据写清哈希迁移方案并在隔离数据上验证；测试合法、错误密码、过期/伪造 token、退出后的访问。不要复制 Java 配置里的任何密钥值。
- **验收**：两用户分别登录并访问自己的信息；无 token 与伪造 token 失败；用户 A 不能用用户 B 的 ID 读取数据；前端现有 `Authorization` 头格式有契约记录。

**004 实施记录（2026-09-24，已完成）**

- Java 入口：`LoginController`（`/api/auth/login`、`/logout`、`/info`）、`AuthService` 与 `user_account` 表；详见[脱敏用户旅程契约](../契约样例/002-用户旅程静态契约.md)。
- Python 入口：`src/gogo_agent/auth/` 模块挂载于 `gogo_agent.api:app` 下的 `/api/auth` 路由组。实现 `AuthService`、`UserAccountRepository`、`PasswordManager`（PBKDF2-HMAC-SHA256 哈希及旧明文透明平滑升级）与 `TokenManager`（支持签发、校验与主动注销撤销）。
- 验证命令与结果：运行 `uv run pytest tests/test_004_auth.py -v`，全部 8 项测试通过：包含两用户隔离登录查自身信息、管理员角色校验、错误账密 400 拦截、无 Token/伪造/过期/注销后 Token 401 拦截、前端原生 `Authorization: <token>` 及 `Bearer` 格式兼容，以及旧明文密码在首次登录时自动升级为安全哈希并写回仓储。
- 差异/待办：当前为隔离测试轻量仓储，后续 005 与数据库正式接入时复用相同接口对接 MySQL；彻底消除了 Java 原项目的明文密码直接比对风险。

### [x] 005 会话与消息持久化 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/005_✅会话与消息的持久化.md>)

- **理解**：区分 `chat_conversation`、`chat_message` 业务历史与 AgentScope Java `agentscope_session` 状态；理解一次请求结束、进程重启和跨用户读取时各自应保留什么。
- **动手**：实现会话创建/查询、消息保存/查询、标题更新的 Python 仓储和 HTTP 接口；为 AgentScope 2.x 的 Agent 状态单独选择持久化方式，不直接读取 Java 的序列化字节，也不照搬 Java 已废弃的“影子历史”路径。写入用户消息、Agent 回复与会话所有者时使用同一可信身份。先支持简单文本对话，挂起/恢复细节在 092/097 补齐。
- **验收**：用户 A 创建会话、发两轮消息、重启服务后历史仍在且顺序正确；用户 B 查同一 session 返回拒绝或不存在；业务消息与 Agent 内部状态的存储位置有明确说明。

**005 实施记录（2026-09-24，已完成）**

- Java 入口：`ChatController`（`/api/chat/{sessionId}`、`/{sessionId}/title`、`/{sessionId}/messages/{messageId}/feedback`、`/{sessionId}`、`/conversations`、`/{sessionId}/messages`）；`ChatHistoryService` 与 `chat_conversation` / `chat_message` 表；AgentScope Java `agentscope_session` 表与 Hook；详见[脱敏用户旅程契约](../契约样例/002-用户旅程静态契约.md)。
- Python 入口：`src/gogo_agent/chat/` 模块挂载于 `gogo_agent.api:app` 下的 `/api/chat` 路由组。实现 `ChatHistoryService`、`ChatAgentExecutor`、`ChatHistoryRepository`（支持内存与 MariaDB）、`AgentSessionStore`（支持内存与 MariaDB `agentscope_session`）。
- 架构分层与存储定位说明：
  1. **L1 业务会话与消息持久化**：存储于 `chat_conversation` 与 `chat_message` 表，用于前端历史展示、点赞点踩与标题管理，采用逻辑软删除（`deleted=1`）。
  2. **L2 Agent 对话记忆与推理状态**：存储于 `agentscope_session` 表，序列化 AgentScope 2.x 原生 `AgentState` JSON（含推理上下文、中间 block 及 usage），不读取 Java 序列化字节，实现服务重启后多轮上下文无缝恢复。
  3. **可信身份与安全收敛**：会话操作完全依赖 Token 解析出的 `current_user.user_id`；彻底修复并收敛了 Java 源码中 `ensureConversationExists` 不校验已有会话归属的潜在安全隐患，用户 B 访问或写入用户 A 的会话均严格返回 HTTP 403。
- 验证命令与结果：
  - 针对性测试：运行 `uv run pytest tests/test_005_chat.py -v -s`，全部 9 项测试通过；运行全量测试 `uv run pytest`，全部 35 项测试通过。
  - 跨重启与多轮记忆：验证了两轮消息顺序正确；验证了模拟服务重启后 AgentState 上下文完整保留并持续追加至 4 条消息。
  - 越权防御拦截：覆盖用户 B 试图读消息、发消息、改标题、删会话、提交反馈，全部被 HTTP 403 成功拦截且用户 B 会话列表完全隔离。
  - 真实模型调用验证：已配置并验证真实大模型端到端调用，模型返回有效中文问候回答：“我是 GoGo 差旅助手，专注于为您提供高效、省心的差旅申请、行程规划与预订服务。”
  - 真实数据库验证：在真实 MariaDB 上完成表结构初始化、`chat_conversation` / `chat_message` / `agentscope_session` 读写与更新验证。
- 差异/待办：005 完成了基础文本对话、两层持久化以及标准 SSE / JSON 输出支持；挂起/恢复（HITL）、打断逻辑将在 092/097 补齐，高级 SSE 事件流将在 098 细化。阶段 A 全部 001–005 目标已圆满达成，可平稳进入阶段 B。
