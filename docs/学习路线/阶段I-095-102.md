### [ ] 095 RAG 知识库 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/095_✅接入RAG 知识库，让 Agent 拥有领域知识.md>)

- **理解**：Java 有政策/指南的本地文档知识库与景点托管知识库；信息 Agent 选择性检索。政策精确额度应以业务规则工具为准，不由相似文本猜测。
- **动手**：汇总 014 的意图样例索引、034 的政策库和信息 Agent 的景点/签证资料，分别定义导入、重建、检索、来源引用与空召回行为；只迁移实际启用的语料。
- **验收**：固定问题能取回正确版本的相关片段，回答标注来源；无命中不编造；数值政策判断仍调用确定性工具。

### [ ] 096 MCP 与 Skill 外部能力 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/096_✅外部能力集成 — MCP 与 Skill.md>)

- **理解**：MCP 是工具协议，Skill 是能力说明/调用流程，CLI 是进程边界；三者不能用同一套无差别重试或权限。
- **动手**：对天气、签证及保留的旅行 Skill 建最终注册清单，写连接/关闭、超时、允许工具、凭证注入和失败降级；移除迁移过程中遗留的重复入口。
- **验收**：只发现和调用批准的工具；服务不可用时主流程给出可理解的失败或部分结果；凭证与用户状态不串。

### [ ] 097 Human-in-the-Loop 结构化交互 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/097_Human-in-the-Loop — Agent 与用户的结构化交互.md>)

- **理解**：Java `ask_user` 会挂起当前 Agent，`/api/chat/respond` 用 `toolUseId` 恢复；流结束可能表示等待用户，并非完成。AgentScope 2.x 的权限/交互事件需按锁定版本验证。
- **动手**：定义 text/select/multi-select/confirm/form 等交互请求与响应 schema；保存待处理工具 ID、session、用户、动作、过期时间和恢复状态。让恢复请求经过会话所有权与动作匹配校验，再把回答送回 Agent。
- **验收**：正常回答、取消、超时、错误 `toolUseId`、重复回答、跨用户 session 都有确定结果；挂起期间不继续执行待确认写操作；跨进程恢复可用。

### [ ] 098 SSE 流式推送 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/098_实时通信 — SSE 流式推送架构.md>)

- **理解**：现有前端用 POST 返回 SSE，`event:` 和多行 `data:` 的解析已有具体实现；后端事件的**名称、payload、顺序和完成语义**都属于契约。
- **动手**：逐项列出并复刻现行前端实际消费的 `message`、`message_id`、`progress`、`thinking`、`plan_update`、`travel_data`、`booking_result`、`plan_html`、`user_interaction`、`suggestions`、`interrupted`、`error` 等事件；将 AgentScope 2.x 内部事件映射到这一个权威外部协议。测试分块、断连、完成、挂起和恢复。
- **验收**：把 Java `frontend/src/api/chat.ts` 的流解析器用于 Python 后端时，完整消息、进度与交互卡片正确呈现；一个挂起流不能误发完成。前端有未使用的 `/api/chat/{sessionId}/confirm` 辅助函数，而 Java 控制器没有该路由；核对是否真有调用，不为未使用函数凭空新增后端接口。

### [ ] 099 A2A 跨域 Agent 通信 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/099_引入A2A实现跨域Agent通信.md>)

- **理解**：源项目只在未完成的报销 Agent 注释中提到 A2A；它不是现有功能等价迁移的一部分。
- **动手**：写一页采用条件：何时需要远端 Agent、身份/数据边界、超时/回调、与进程内子 Agent 的比较。只有后续单独确定报销等跨域需求，才做 AgentScope 2.x A2A 小实验。
- **验收**：当前迁移报告明确写“未实现/仅设计”；不会因为框架支持 A2A 就假报业务链已完成。

### [ ] 100 缩短执行链路 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/100_为了缩短执行链路，做了哪些优化？.md>)

- **理解**：优化点包括快速识别、条件改写、缓存、只读并行、模型分工；当前 Java 高置信单意图直跳已被回滚。
- **动手**：用固定请求集记录各阶段耗时、模型/工具调用次数、正确路由率；一次只改变一个优化点，并比较前后结果。
- **验收**：耗时或成本下降且契约、路由、权限结果不退化；无收益的机制移除；直跳若要恢复需单独验证上下文和结果整合。

### [ ] 101 多 Agent 通信方式 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/101_多智能体之间通信方式如何选择？.md>)

- **理解**：进程内子 Agent 调用、数据库会话、Redis 候选/计划存储、Redis 中断广播各解决不同问题。
- **动手**：画一张通信图，列消息/状态的生产者、消费者、user/session 关联、超时、重试、去重和恢复策略；收敛同一状态的重复写入路径。
- **验收**：给任意一次中断或计划读取，能指出唯一权威存储与消息来源；跨用户引用、迟到广播和重复事件不会影响新执行。

### [ ] 102 会话管理与集群部署 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/102_会话管理与集群部署 — 生产级Agent 系统.md>)

- **理解**：Java 的本地 Agent 缓存、Emitter 注册表、MySQL Session 和 Redis 广播各有边界；静态代码存在不等于已在多节点跑通。
- **动手**：写 Python 部署配置、健康检查、数据库迁移与共享存储配置；启动至少两个进程，演练登录、对话、挂起、跨进程回复、打断、重启恢复与用户隔离。最后把 Java 项目的 `frontend/` 复制到 Python 工作区，只调整必要的 API 地址配置并做浏览器验收。
- **验收**：用户能在原前端完成已迁移的登录、差旅单、规划、审核、预订模拟、审批、HITL 对话；两进程切换不丢会话或串用户；外部真实供应商和生产数据验证结果单独标记。
