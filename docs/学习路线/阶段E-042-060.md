# 阶段 E：行程规划、审核与外部能力（042–060）

[学习路线首页](README.md) · [阶段 D](阶段D-029-041.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：可追踪的行程计划、确定性方案计算、受控旅行信息查询、独立审核结果与外部凭证边界。所有供应商写操作仍用模拟服务。

### [ ] 042 为什么规划使用 Plan-and-Execute

- **理解**：规划涉及收集条件、并行找候选、组合、审核和可能重做；单次模型回答无法可靠表示步骤状态。
- **动手**：定义计划步骤、输入/输出、完成/失败/待确认状态和终止条件；对照 Java 规划过程，评估 AgentScope 2.x 的计划能力是否能表达这些状态。
- **验收**：中途搜索失败和用户改日期时，能指出从哪一步重新执行，已确认的订单写操作不会重复。

### [ ] 043 行程规划智能体

- **理解**：看 Java `ItineraryPlanAgent` 的工具、提示词和结果存储；区分“提出候选方案”与“执行预订”。
- **动手**：构建 Python 规划 Agent，先接模拟搜索和确定性方案工具；把规划状态存到会话关联的计划记录，返回可引用的 `plan_id`。
- **验收**：输入城市、日期、预算能得到有来源的方案；参数不足时请求补充；没有确认时不下单。

### [ ] 044 为什么方案设计做成工具

- **理解**：交通/酒店的价格、时间和政策计算可确定，模型适合解释权衡，不适合暗算评分。
- **动手**：把组合/排序函数放在普通 Python 业务模块，再用 `FunctionTool` 或锁定版本等价 API 暴露；写选择依据短记录。
- **验收**：直接调用业务函数与 Agent 经工具调用得到相同评分；提示词变化不改变计算结果。

### [ ] 045 行程方案设计工具细节

- **理解**：追 Java 规划工具的去程、住宿、返程组合、时间价格归一化、政策软约束和偏好评分。
- **动手**：用固定机票/酒店候选集逐项移植过滤、组合、评分与代表方案选择；每项中间值可打印或测试。
- **验收**：相同候选输入下，Python 与 Java 的入选/淘汰原因和排序可对照；空候选、异常价格、跨时区航班有明确结果。

### [ ] 046 目的地实时联网查询

- **理解**：实时天气/新闻等数据有来源、抓取时间和有效期；失败不能变成模型编造的确定事实。
- **动手**：对 `DestinationLiveTools` 建 Python 客户端与返回 schema；设置超时、可用性错误和来源时间字段。
- **验收**：模拟正常、超时、无结果三种响应；最终回答能区分查到的数据和未验证的信息。

### [ ] 047 天气 MCP 接入

- **理解**：MCP 客户端有连接/关闭生命周期、工具发现和参数 schema；它与普通 HTTP API 工具同属外部能力但协议不同。
- **动手**：按锁定版本的 AgentScope 2.x 官方 MCP 文档接入现有天气服务；先连测试服务，记录工具列表和错误转换。
- **验收**：可以列出并调用天气工具，断连/超时有可复现结果；不向 MCP 服务发送不必要的用户隐私。

### [ ] 048 旅行 Skill/MCP 对比

- **理解**：一个供应商可能提供 Skill、MCP、CLI 等多个入口，重复接入会导致能力和凭证双轨。
- **动手**：核查源项目当前实际启用的途牛、航班管家、Rolling Go、天气及签证能力，建立“用途、入口、只读/写入、凭证、状态、保留与否”清单。
- **验收**：每个行为只有一个计划中的权威调用入口；未启用的旧 Skill 不被误迁移。

### [ ] 049 途牛 Skill

- **理解**：阅读现有 tuniu CLI 的输入、结构化结果、错误码与凭证注入方式，识别搜索与下单的不同风险。
- **动手**：先做搜索客户端/适配器和模拟 CLI 响应，不运行真实下单；隔离执行目录和参数，保留供应商原始请求 ID。
- **验收**：固定搜索样例得到规范化候选；命令失败、非 JSON、超时均能返回错误且不把密钥写入日志。

### [ ] 050 航班管家 Skill

- **理解**：核查 Java `FlightApiKeyHook` 与现有 Skill 的真实调用链和所需凭证。
- **动手**：建立可替换的航班查询适配器，用假结果验证航班号、时间、舱位、价格的转换；如果源端未实际启用某功能，只记录而不多造一条路径。
- **验收**：同一航班样本转换稳定；无授权或上游限流有明确错误；与途牛候选来源不混淆。

### [ ] 051 Rolling Go Skill

- **理解**：酒店平台可能在本地工作目录、Token 或浏览器状态中保留登录态；多用户隔离是核心要求。
- **动手**：按用户/会话分配工作空间与凭证引用，封装只读酒店搜索；测试结束清理临时状态。
- **验收**：两用户并发搜索不共享 Token、文件或候选；过期登录态会要求重新授权而非复用别人状态。

### [ ] 052 为什么审核使用子 Agent

- **理解**：审核需独立阅读完整计划并提出结构化问题；精确金额与日期规则仍应由确定性工具判断。
- **动手**：写审核职责说明，定义审核 Agent 可读字段、不可执行动作、输出的“通过/修改/拒绝”判定边界。
- **验收**：审核 Agent 看得到自己应审的计划，但不能修改订单或调用供应商下单工具。

### [ ] 053 行程审核智能体

- **理解**：Java 的审核维度涉及完整性、时间、出发目的地、预算、偏好和路径，输出需能被程序读取。
- **动手**：建立 `ReviewResult` schema 和审核 Agent，接入只读计划与政策工具；每条问题包含维度、严重程度、证据和建议。
- **验收**：完整计划可通过，冲突计划能指出具体字段；无效模型输出不被当作通过。

### [ ] 054 最终审核工具

- **理解**：最终校验是模型意见之外的硬规则检查，应防止遗漏关键数据。
- **动手**：移植 `ItineraryReviewTools` 中的确定性检查并单独测试，审核 Agent 将其结果合并进最终结构化结论。
- **验收**：空方案、超预算、日期冲突、不匹配出发地会被拦住；工具失败不能被模型口头“审核通过”覆盖。

### [ ] 055 第三方鉴权总览

- **理解**：区分服务级 API Key、用户级 OAuth Token、CLI 环境变量和 MCP 凭证；每一种的归属、更新与过期不同。
- **动手**：画“用户→服务→供应商”的授权图，为每个实际集成记录凭证持有者、可访问资源和撤销方式。
- **验收**：能回答某次供应商请求使用谁的授权；无法授权时不会用其他用户或管理员的密钥兜底。

### [ ] 056 直接 Token 配置

- **理解**：配置型 Token 只适合与实际服务契约相符的场景，不能写进提示词、源码或持久化日志。
- **动手**：实现服务端安全读取与请求头注入；只在发往目标供应商时使用，错误中屏蔽 Token。
- **验收**：缺 Token 请求不发出；单元测试能验证头部已注入但日志/异常中没有明文。

### [ ] 057 OAuth PKCE 与本地回调

- **理解**：PKCE 的 `state`、`code_verifier`、授权码交换与过期刷新；先核对源项目是否对相应平台实际使用。
- **动手**：为真实需要的平台实现发起授权、回调校验、令牌存储/刷新；本地测试使用模拟授权服务器，不在脚本里放真实回调密钥。
- **验收**：正常登录可恢复原用户会话；错误 `state`、过期 code、重复回调和跨用户 Token 均失败。

### [ ] 058 外部 Skill 的生产可用性

- **理解**：外部 CLI/Skill 的退出码、超时、标准输出格式、工作目录和资源占用都可能失控。
- **动手**：给保留的每个 Skill 加输入限制、超时、错误映射、输出解析、用户隔离和清理；不将任意 shell 文本直接拼进命令。
- **验收**：模拟长时间挂起、非法 JSON、巨大输出和进程退出失败，Python 服务均能返回可定位错误且不泄露凭证。

### [ ] 059 API Key 动态管理、加密和脱敏

- **理解**：对照 Java `ApiKeyService`、`SecretCipher`、`SensitiveMasker`；区分加密存储与展示脱敏。
- **动手**：实现用户级凭证增删查、加密与密钥轮换预案；在 API、日志、工具响应和模型上下文中只暴露最小必要信息。
- **验收**：数据库里无明文 Key；用户只能管理自己的 Key；更新/撤销后旧 Key 不再被调用；负例日志检查无明文。

### [ ] 060 ReviewAgent 获取 PlanAgent 结果

- **理解**：长计划可通过 `plan_id`/计划存储传递，不需要把整份结构反复塞进提示词。
- **动手**：建立计划读写仓储和所有权校验；审核 Agent 根据 `plan_id` 取确定版本并记录审核使用的版本号。
- **验收**：同一版本计划可重复审核；计划修改后旧审核不能误标为新计划通过；跨用户 `plan_id` 访问失败。

## 阶段验收

用模拟外部响应完成“差旅单 → 搜索候选 → 方案计算 → 审核”。记录每一步数据来源与版本；不触发真实下单。通过后进入[阶段 F](阶段F-061-067.md)。
