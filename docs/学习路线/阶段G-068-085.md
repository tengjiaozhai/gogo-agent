### [x] 068 注意力引导 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/068_✅提示词工程——注意力引导.md>)

- **理解**：模型更容易忽略长提示词中分散的关键约束；优先级应能被识别，不能和服务端权限相冲突。
- **动手**：整理每个 Agent 的最高优先级任务、禁止动作和完成标准，迁移 Java 真实使用的提示词段落；建立 5–10 条固定问答。
- **验收**：关键边界样例通过；提示词调整有版本和对照结果，不因强调语句替代代码校验。

### [x] 069 Prompt 中的工具说明 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/069_✅提示词工程——要不要在prompt中写清楚工具该怎么用？.md>)

- **理解**：工具说明帮助模型选择工具，参数 schema 才是输入契约；重复说明会相互矛盾。
- **动手**：核对 Toolkit 中每个工具的名称、docstring、参数与 Prompt 指引；删除过期工具名，只保留何时调用/何时不要调用。
- **验收**：固定样例中模型选对工具、参数有效；已删除的 Java 工具不会出现在 Python 提示词里。

### [x] 070 角色与人格 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/070_✅提示词工程——角色与人格设定.md>)

- **理解**：主 Agent 与审核/预订 Agent 的口吻可以不同，但权限和事实不能由人格设定决定。
- **动手**：迁移各角色必要的身份、受众和语气要求，确保用户看到的解释一致；限制冗长寒暄。
- **验收**：相同事实在不同角色回复中不互相矛盾；角色提示词不能促使审核 Agent 下单。

### [x] 071 结构化输出约束 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/071_✅提示词工程——结构化输出约束.md>)

- **理解**：意图、计划、审核和 HITL 的结构化结果是程序间契约；自然语言“看起来像 JSON”不够。
- **动手**：为关键输出写 Pydantic schema，使用锁定版本 AgentScope 2.x 的结构化输出接口；定义一次解析失败如何报告或重试。
- **验收**：有效输出可解析，无效字段、未知枚举、缺失计划 ID 被拒绝；失败不进入订单/审批写入。

### [x] 072 Few Shot · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/072_✅提示词工程——Few Shot.md>)

- **理解**：示例可改进格式和边界，也会增加 token、造成过拟合或携带过时事实。
- **动手**：从回归集中选少量真实易错样例，加入对应 Agent 提示词；记录每个示例要解决的错误。
- **验收**：目标错误减少，其他样例不明显变差；没有效果的示例移除。

### [x] 073 Step-back Prompting · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/073_✅提示词工程——Step-back Prompting.md>)

- **理解**：Java 改写提示词已写 Step-back 规则：先澄清过于具体、模糊或带假设的问题，但最终改写须保留原来的具体诉求。
- **动手**：把现行改写规则迁移到 Python 提示词，不增加独立的第二次模型调用；用固定样例验证抽象辅助不会覆盖原问题细节。
- **验收**：复杂场景质量有对照提升；简单查询延迟不被无意义增加。否则只记录“不实施”。

### [x] 074 Reflexion · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/074_✅提示词工程——Reflexion.md>)

- **理解**：Java 规划提示词已有“审核失败→真实修订→重算→再审”的闭环，最多修复两轮；反思不是无限自我对话。
- **动手**：在固定失败样例上迁移最多两轮修订，保存每轮审核证据；修订必须重新调用规划工具，不仅修改答复文字。
- **验收**：可复现地修正具体错误，无法修正时停止并报告；不会循环下单或无限调用模型。无收益则不保留。

### [x] 075 决策表与路由表 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/075_✅提示词工程——决策表 _ 路由表.md>)

- **理解**：模型提示词的路由表不应和服务端 012–020 的意图调度冲突。
- **动手**：把“意图→Agent→允许工具→需确认动作”整理成可审查的表，核对 Java 现行路径与 Python 配置。
- **验收**：同一意图没有两条互相矛盾的调度规则；被注释的高置信直跳不进入现行表。

### [x] 076 动态变量注入 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/076_✅提示词工程——动态变量注入.md>)

- **理解**：当前时间、认证用户、计划 ID 等在每轮可能变化；系统提示词里不能保存过期时间或模型可改的身份。
- **动手**：在 Agent 调用边界从服务端注入可信时间、会话和可见资料；对权限字段只传工具上下文，不接受模型覆盖。
- **验收**：跨日/跨时区测试使用正确时间；模型伪造用户身份不生效；动态变量不会污染其他用户会话。

### [x] 077 职责边界与拒绝策略 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/077_✅提示词工程——职责边界与拒绝策略.md>)

- **理解**：能力缺失、无权限、政策禁止、外部失败是不同情形，回复与后续动作应不同。
- **动手**：为每个 Agent 定义可处理请求和转交/拒绝条件，用固定样例覆盖无权限下单、资料缺失与不相关提问。
- **验收**：拒绝时说明具体原因和可继续的下一步；不会用虚构结果掩盖工具失败。

### [x] 078 记忆自动压缩 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/078_✅上下文工程——记忆自动压缩.md>)

- **理解**：会话历史过长会影响上下文与成本；压缩不能丢掉已确认的日期、预算、授权和待执行动作。
- **动手**：用锁定版本 AgentScope 2.x 的上下文压缩能力或明确的压缩服务，设置触发阈值与保留字段；准备长对话样例。
- **验收**：压缩后关键事实可准确回忆，token 数量下降；用户撤回或修正的旧事实不会重新出现。

### [x] 079 第三方 Skill 瘦身 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/079_✅上下文工程——如何对第三方Skill瘦身.md>)

- **理解**：第三方 Skill 文档可能很长、工具多且含无关操作；全文常驻上下文会增加成本和误用。
- **动手**：只保留实际启用的 Skill 能力、参数、权限和错误说明；记录原始版本及删减依据。
- **验收**：所需搜索/预订模拟用例仍可运行，模型不再调用无关命令；压缩前后上下文大小可比较。

### [x] 080 工具返回内容裁剪 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/080_✅上下文工程——工具返回内容裁剪.md>)

- **理解**：搜索结果、CLI JSON 与 MCP 元数据可能很大；裁剪前应区分决策字段与噪音。
- **动手**：给候选、价格和来源定义白名单字段与数量上限；必要时保存完整原始响应，仅向模型传摘要和引用 ID。对 Java `CliResultCompressHook` 的去重/去空规则做样例对照。
- **验收**：输出体积下降，价格/币种/时间/政策/供应商 ID 以及数值 `0`、布尔 `false` 不丢；不能因为裁剪把失败结果变成成功。

### [x] 081 系统提示词与 KV 缓存 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/081_✅上下文工程——优化系统提示词利用KV缓存.md>)

- **理解**：稳定的提示词前缀有利于支持缓存的模型复用，但缓存效果取决于模型供应商与实际请求格式。
- **动手**：把固定角色说明和动态时间/用户信息分开；在当前模型服务上测请求耗时和缓存指标（若能获得）。
- **验收**：有可比较样例与指标；无实际收益时不增加特殊处理。

### [x] 082 上下文缓存 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/082_✅上下文工程——上下文缓存.md>)

- **理解**：本节原文还讨论模型请求的显式 `cacheControl`；Java ReAct Agent 已设置，但单次改写/识别没有同样设置。不要把它与第 039/082 项的业务查询缓存混为一谈。
- **动手**：核对锁定版本的模型提供商是否支持显式上下文缓存，按当前 Java 真正启用的 Agent 范围迁移请求参数；同时定义用户/会话数据的隔离与失效。
- **验收**：实际请求能看到缓存标记和命中/成本指标（若服务支持）；参数重建不丢标记；跨用户私有上下文不被复用。

### [x] 083 中间文件减少 token · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/083_✅上下文工程——利用中间文件减少token消耗.md>)

- **理解**：大候选集或 HTML 不必每轮完整送入模型；Java 当前主要用 Redis 存计划和搜索候选，标题中的“文件”不能机械照搬。
- **动手**：为大结果建立受控中间存储，向 Agent 传摘要和引用 ID；参照 Java 的用户/行程键与 24 小时 TTL，设置隔离、过期和清理规则。
- **验收**：Agent 能按授权重新读取完整结果；过期或他人的引用不可访问；token 下降且方案选择不退化。

### [x] 084 Skill 正文折叠 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/084_✅上下文工程——Skill正文折叠.md>)

- **理解**：Skill 正文在当前轮指导操作，后续会话反复回放全文可能浪费上下文。
- **动手**：对旧历史中已使用的 Skill 内容在本轮模型输入里保留名称、版本、决策结果和必要限制，折叠重复正文；核对框架是否已有等价能力。原始持久记忆保持可追溯，不原地破坏。
- **验收**：多轮调用不重复塞入全文，仍能正确使用 Skill；重新需要时可加载原文；失败追踪可找到原始版本。

### [x] 085 长期记忆 · [原文](</Volumes/PortableSSD/docs/tengjiaozhai.github.io/thoughts/085_✅上下文工程——长期记忆.md>)

- **理解**：会话记忆、业务记录与长期偏好不同；用户说“以后都坐高铁”也可能被撤回。
- **动手**：定义偏好写入/召回/更新/删除的显式权限与来源，接入选定的长期记忆实现；先用两个测试用户验证隔离。
- **验收**：新会话可召回本人的有效偏好；撤回后不再生效；不会引用另一个用户的记忆或把过时偏好当硬规则。
