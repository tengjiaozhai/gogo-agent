# 阶段 H：执行闭环、安全与多实例恢复（086–094）

[学习路线首页](README.md) · [阶段 G](阶段G-068-085.md) · [原始目录](/Volumes/PortableSSD/docs/tengjiaozhai.github.io/目录.md)

**阶段产物**：能够观察、打断、恢复的执行链；用户和工具执行隔离。先在单进程验证状态，再用两进程/共享存储验证集群行为。

### [ ] 086 行程规划的执行闭环

- **理解**：计划、执行、观察、校验、修订是循环；任何步骤失败都必须知道下一步与终止条件。
- **动手**：把阶段 E 的计划状态、候选和审核结果连成一条可恢复工作流；为失败、用户补充信息、审核退回设状态转换。
- **验收**：模拟天气失败、无候选、审核不通过、用户修改预算，各自能进入正确分支；不重复之前的订单写入。

### [ ] 087 分层记忆体系

- **理解**：当前请求上下文、聊天历史、Agent 内部状态、业务事实和长期偏好有不同权威来源与生命周期。
- **动手**：画状态/记忆地图，给每层标所有者、存储、读取者、TTL、清理与恢复条件；删除职责重复的副本或标明只读投影。
- **验收**：可解释“修改行程预算”后哪些层更新、哪些必须失效；重启后不会让旧提示词覆盖新数据库事实。

### [ ] 088 命令执行安全护栏

- **理解**：旅行 Skill 使用 shell/CLI 时，命令注入、工作目录越界和密钥泄露都是真实边界；不能把模型文本拼接进 `sh -c`。
- **动手**：为确需 CLI 的能力改成参数数组、允许的可执行文件和固定工作目录；对路径和参数做校验、超时与输出限制。
- **验收**：包含分号、换行、命令替换、上级目录的恶意输入被拒绝；正常模拟 CLI 调用仍可执行。

### [ ] 089 沙箱

- **理解**：先核对 Java 是否真的运行不可信代码；AgentScope 2.x 有隔离能力，但不等于每个外部工具都需要独立沙箱。
- **动手**：若保留能执行外部命令的 Skill，做本地受限运行与框架沙箱的最小比较，明确文件、网络、CPU/内存和凭证边界；源端没有需求时写“不实施”及原因。
- **验收**：演示越权文件/网络访问被阻止或证明工具只需受限参数执行；不能仅凭“启用沙箱”字样声称安全。

### [ ] 090 可观测性

- **理解**：有日志不等于能还原一次 Agent 执行；需把 HTTP 请求、会话、Agent、模型、工具与外部请求关联起来。
- **动手**：建立结构化事件和最小指标：请求 ID、用户内部 ID、session、agent、tool、耗时、错误类别、token（可得时）；在错误路径也保留关联信息。
- **验收**：给定一次模拟规划失败，能从请求定位到失败工具与上游响应类别，且日志不包含明文密钥或不必要个人信息。

### [ ] 091 全链路敏感信息脱敏

- **理解**：日志、API、SSE、异常、模型提示词、工具结果都可能泄露 API Key、联系方式和订单信息；“显示时打码”不等于存储安全。
- **动手**：列敏感字段清单和每个出口的处理规则；对日志过滤、响应字段和异常包装添加测试。
- **验收**：向测试数据注入标记型密钥/手机号，在各出口搜索不出现不该出现的明文；授权用户仍能完成必要操作。

### [ ] 092 集群下 Agent 打断与恢复

- **理解**：Java 使用本地活跃 Agent 缓存、共享 Session 与 Redis 中断广播；AgentScope 2.x 自带状态/事件能力需实测，不假定可直接兼容 Java 序列化状态。
- **动手**：先完成单进程中断/续跑状态机，再启动两个 Python 进程和共享存储，模拟进程 A 开始、进程 B 打断或恢复；明确挂起工具输入的持久化格式。
- **验收**：打断后不会继续下单；进程退出后用户可在另一进程恢复同一待处理会话；重复恢复只生效一次。

### [ ] 093 Agent 编排与智能调度

- **理解**：当前 Java 主要是固定 Pipeline + Master 调度，不应因为框架提供更多编排模式就再造第二套权威路径。
- **动手**：检查阶段 B/C/H 的调度职责是否重叠；只对可证明的依赖/并行场景使用 AgentScope 2.x 编排能力，记录输入、输出和状态所有者。
- **验收**：一次请求的调度路径唯一、可追踪；写入步骤不会被并行调度或重复 Agent 接管。

### [ ] 094 用户级鉴权隔离

- **理解**：004/028 已建立身份基础，本节覆盖存储、缓存、外部 Skill 工作区、SSE 与 Agent 状态的全链路所有权。
- **动手**：建立两个用户、两个进程的权限矩阵；对会话、差旅单、计划、预订、API Key、长期记忆、缓存和中间文件逐项测试。
- **验收**：用户 A 猜到 B 的任何 ID 或接收到 B 的事件都不能读取/修改 B 的资源；后台任务不继承过期用户上下文。

## 阶段验收

模拟一次有工具超时和用户确认的规划过程，完成“日志定位 → 打断 → 跨进程恢复 → 正确继续”，并运行跨用户负例。通过后进入[阶段 I](阶段I-095-102.md)。
