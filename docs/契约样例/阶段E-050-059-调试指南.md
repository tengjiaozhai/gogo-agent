### 本编号用到的 Python 语法与生命周期

| 语法/对象 | 用在哪 | Java 工程师怎么理解，以及不等价处 |
| --- | --- | --- |
| `with` 与 `@contextmanager` + `yield` | `flight_manager_key.user_scope`；`with self._session_factory() as session, session.begin()` | 近似 `try { set } finally { reset }` 与 `@Transactional` 的边界：`session.begin()` 的 `with` 正常退出提交、异常退出回滚。**本编号没有使用 `async with`**；020 指南里的 `async with` 是另一处异步资源作用域。 |
| `ContextVar` | `flight_manager_key._current_user` | 对应 Java 的 Reactor Context / `ThreadLocal` 的“当前用户”。不等价：`ContextVar` 按 **asyncio 任务**复制，`asyncio.gather` 里两个任务互不可见；但**线程池不会自动继承**（Java 的 `InheritableThreadLocal` 会继承），所以 051 的线程并发示例把 `user_id` 作为显式参数传入，没有依赖 `ContextVar`。 |
| 生成器 `auth_flow` / `yield request` | `token_header.TokenHeaderAuth` | `httpx` 在发请求前运行 `auth_flow`，遇到 `yield` 把请求发出去。形态近似 OkHttp `Interceptor`，Java 基线里没有用它。这里 `yield` 之前的校验抛错，请求就**不会**到达传输层。 |
| `SecretStr` | `resolve_for_use` 返回值、`TokenSet.access_token` | 类似“`toString()` 返回掩码的包装类”。`get_secret_value()` 是唯一取明文的显式点，可以全局搜索审计。不等价：它只防意外 `print/repr/日志`，防不住有意取值。 |
| `AESGCM.encrypt(nonce, data, aad)` | `cipher.py` | 对应 `Cipher.getInstance("AES/GCM/NoPadding")` + `GCMParameterSpec`；结果是“密文+16 字节标签”，`aad`（关联数据）不加密但参与认证，换了就解不开。Java 的 `SecretCipher` 没用关联数据。 |
| `raise … from None` | `cipher.py`、`apikey.py` | Java 的 `new RuntimeException(msg, e)` 会保留 cause；Python 默认也会链式显示上一个异常。这里 `from None` 主动切断，保证 traceback 里没有底层异常文本。 |
| `threading.Lock`、`ThreadPoolExecutor`、`Barrier` | 模拟授权方、`InMemoryTokenStore`、051 并发 | 近似 `synchronized`/`ExecutorService`/`CyclicBarrier`。内存 SQLite 的 `StaticPool` 是单连接，本编号没有对 `ApiKeyService` 做多线程并发保存测试。 |
| `Protocol` | `TokenStore` | 结构化接口：不需要 `implements`，方法签名对得上即可替换（生产换 Redis 实现）。 |
| `logging.Filter` 挂在 `Handler` 上 | `SensitiveLogFilter` | 对应 logback `conversionRule`。必须挂在 handler 而不是 logger：logger 上的过滤器不处理子 logger 传播来的记录（练习 3 演示）。 |
| `StrEnum` | `CredentialKind`、`CredentialHolder` | 值是字符串的枚举，序列化即字符串。 |


答案：`bob PKCE_VERIFIER_MISMATCH`、`alice PKCE_CODE_REUSED`。任何一次兑换尝试都会消耗授权码，所以截获者即使失败也会让 alice 的这次登录失败，alice 需要重新发起授权。这是“授权码一次性”的代价；它不会让截获者拿到令牌。

- 没有访问任何真实第三方服务，没有运行 Java 应用。Java 侧的结论（清单、PKCE 缺失、Hook 链）来自静态读取源码。

## 完成标准与常见卡点

完成本编号时，你应能：指出 059 里密文变明文的唯一位置（`apikey.py:165`）和明文进入数据库前的位置（`apikey.py:210`）；解释撤销为什么不靠缓存失效；说出 055 里为什么 admin 也解析失败；说出 PKCE 里 `state`、授权码、`verifier` 各自挡住哪类攻击；解释 `ContextVar` 与线程池的差别；并能用 `pytest -k` 复现所有负例。

| 遇到的情况 | 先检查什么 |
| --- | --- |
| 找不到 `gogo_agent` 模块 | 工作目录是否是仓库根目录，是否设置 `PYTHONPATH=src`。 |
| `SECRET_KEYS_INVALID` | `GOGO_SECRET_KEYS` 是否是 `版本:32字节base64url`，用上文命令生成；版本号只能含字母、数字、`_`、`-` 且不超过 16 个字符。 |
| `SECRET_KEY_VERSION_UNKNOWN` / `API_KEY_UNREADABLE` | 密文的密钥版本已从环境变量中移除；先把旧密钥放回配置，调用 `rotate_to_current_key()` 迁移后再删除。 |
| 059 输出里的 `rotated` | 这是脚本给轮换用的临时新密钥版本名，不是你的密钥版本；`key_version_is_current` 用你自己的第一项版本号判断。 |
| 想在真实数据库上跑 | `UserApiKeyModel` 尚未纳入 `init_db.py`；需另行建表后再把会话工厂传给 `create_api_key_service`。 |
