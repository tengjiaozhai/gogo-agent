### 本阶段用到的 Python 语法与生命周期

- **`async def` / `await`**：`await` 让出控制权，等待当前异步步骤完成。像 Reactor 里 `Mono.block()` 之后的同步感，但不会阻塞线程。**不等价**：Reactor 的 `Mono` 要订阅才执行；Python 协程对象只有被 `await` 或包成任务才运行。
- **`asyncio.create_subprocess_exec(program, *args)`**：参数逐个传给操作系统，等价于 Java `ProcessBuilder(List<String>)`，**不是** Java 现有工具的 `bash -c "<文本>"`。`stdin=DEVNULL`、`stdout/stderr=PIPE`、`cwd`、`env` 都在这里设置；`env=` 是**完整**的子进程环境，不是在父环境上追加。`start_new_session=True` 让子进程成为新进程组组长，之后 `os.killpg(pid, SIGKILL)` 才能连孙进程一起杀。Java 对应的是 `Process.destroyForcibly()` 加遍历 `descendants()`，两者做法不同。
- **`asyncio.timeout(秒)`**：上下文管理器，到时间就取消里面正在等待的操作并抛 `TimeoutError`。类似 Reactor 的 `.timeout(Duration)`，但它取消的是当前任务里的 `await`。
- **`asyncio.create_task` 与 `asyncio.wait(..., FIRST_EXCEPTION)`**：`_collect` 并发读 stdout、读 stderr、等进程退出。任意一路抛 `_OutputOverflow` 就立刻返回，不会读完再截断。没有直接对应的 Java 类，最接近 `CompletableFuture.anyOf`。
- **`try / finally`**：`run_json` 的 `finally` 里依次杀进程组、回收（`_reap`）、删除工作目录，所有失败路径都会走到。类似 Java 的 `finally`，**不等价**之处是这里的 `finally` 里也有 `await`，被取消时仍会执行。
- **`async with WeatherMcpService(...) as service`**：进入时 `await connect()`，退出（含异常）时 `await close()`。类似 try-with-resources，只是协议是 `__aenter__/__aexit__` 而不是 `AutoCloseable`。
- **专用生命周期任务**：`WeatherMcpService._lifecycle` 在自己的任务里完成 `MCPClient.connect()`、等待关闭信号、再 `close()`。原因：AgentScope 内部用 anyio 的取消作用域，要求进入与退出在同一任务；握手超时等失败时它会留下一个持续取消宿主任务的作用域，放在专用任务里就不会波及调用方。Java 没有对应问题。
- **`asyncio.Event`**：`_ready`、`_closing` 两个一次性信号，类似 `CountDownLatch(1)`，但可复用。
- **`StrEnum`**：`SkillErrorCode.TIMEOUT.value == "TIMEOUT"`，可以直接当字符串比较，类似带字符串值的 Java 枚举。
- **Pydantic `frozen=True`**：`SkillPolicy`、`CatalogEntry` 创建后不可改；`model_copy(update=…)` 得到新对象，**不重新校验**，所以测试里的负例可以直接构造非法组合。

`_validate_args` 的顺序是：类型与大小 → `denied_tokens` → 前缀白名单 → 尾部路径检查。路径参数前缀合法，只在最后一关因 `/etc` 被拒；写命令在 `denied_tokens` 一关就被拒；整串文本在第一关因不是列表被拒。这里 `fixed_args` 用了相对路径，但五组都在启动前被拒，所以没有影响；**真正运行时 `fixed_args` 必须是绝对路径**，因为子进程的 `cwd` 是隔离目录，相对路径会找不到脚本（退出码 2）。

**已知缺陷与风险（不是测试能消除的）**：

- AgentScope 2.0.8 的 `MCPClient.connect()` 在握手被取消或 stdio 服务启动即退出时，清理发生在另一个任务里，会留下异常日志并**可能遗留 stdio 子进程**。专用生命周期任务防止了对调用方任务的污染，但无法清理遗留子进程；测试里的假服务用有限睡眠自行退出，避免遗留。生产环境需要进程监督。
  - 复跑观察（2026-10-11，超时与启动即退出六类场景）：功能结果全部正确，进程结束后没有遗留 `fake_weather_mcp_server.py`；但 `asyncio.run` 关闭阶段仍打印 `RuntimeError: Attempted to exit cancel scope in a different task than it was entered in`，stderr 中还有假服务端的 broken pipe 栈。该噪声未被测试断言。
- 隔离只靠 cwd/`HOME`/`TMPDIR` 与路径类参数拒绝，**没有内核级沙箱**；被执行的 CLI 若用绝对路径仍可写目录之外。
- 进程树清理只支持 POSIX，且清不掉自己 `setsid` 脱离进程组的孙进程。
- 046 的有效期（天气 3 小时、资讯 6 小时）是 Python 新增的假设值，Java 没有该概念。
- 与 Java 的已知偏差：资讯主题只接受 Java 工具说明里列出的七个；缺酒店名称、缺时间的条目被跳过而不是带空值传下去；NaN/Infinity 价格按 0 处理；翻页与按 Redis field 精确读取没有迁移。

## 常见卡点

- **`fixed_args` 写了相对路径** → 子进程退出码 2，stderr 里有 `can't open file …/r_xxxx/scripts/…`：子进程的 cwd 是隔离目录，要用绝对路径。
- **`env` 里放了白名单外的名字** → `INVALID_ARGUMENT`。在 `TuniuCliAdapter(extra_env=…)` 里传的名字会自动加入白名单；需要 `PATH` 时也在这里传。
- **输出被 `grep` 之类管道缓冲后看起来“卡住”**：用 `python -u`，或直接不加管道。
- **047 比其他场景慢**：关闭挂起的假服务要等 AgentScope 的 5 秒终止流程，这是预期。
- **看到 `Process group termination failed … falling back to simple terminate`**：来自 `mcp` 包终止挂起服务的日志，随后会退回普通终止，预期出现。
