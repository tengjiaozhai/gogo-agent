# 执行过程时间轴：Java 组件复用与 Python 事件调试

本次按用户要求提前恢复思考、主子委派和工具详情展示，不代表 098 的所有丰富事件、HITL、打断或集群恢复已经完成。前端继续使用 Java 迁入的 `AgentMessageBlock`；Python 只转发实际发生的事件，不用回答文本猜测工具是否执行。

## 1. 从页面看一轮请求

新发一条消息后，回复区域按顺序显示：主 Agent 状态 → 本轮思考（模型返回时）→ 委派工具 → 子 Agent 状态与思考 → 子工具 → 主 Agent 后续思考 → 回复。

- 点“查看本轮识别与可用工具”，看服务端识别意图和实际注册的工具。工具可用不等于模型调用了它；具体选择看下方委派项。
- 点“深度思考”，展开模型实际返回的文本。没有 `ThinkingBlock` 时明确显示“本次调用未返回可展示的思考内容”。本次不改变现有 `thinking_enable=False` 模型参数；有些网关仍会返回 thinking，有些不会。
- 点工具行，展开完整文本参数与结果。文本内容先经现有 `SensitiveMasker` 脱敏；不展示 SDK 的凭证、系统提示词或整个模型请求。
- `CONFIRMATION_REQUIRED` 和 `NEEDS_INPUT` 显示“待用户处理”；其他 `success=false` 的业务工具结果和 SDK 的 error/denied/interrupted 结果标为失败。子工具失败后 Agent 仍可能正常回答，因而“Agent 执行完成”不代表每个业务工具成功。
- 本轮成功保存后，刷新或重新打开会话，从 `GET /api/chat/{sessionId}/messages` 的 `extra.timeline` 恢复同一时间轴。

旧消息没有保存 `timeline` 时继续显示原正文，不从最新 AgentState 拼造旧轮次过程。整个请求生成失败、取消或断开连接时不保存成功的助手回复/AgentState，已收到的进度仅在当前页面保留；已有的数据库保存错误也不会因本次前端接线自动修复。

## 4. Java 到 Python 的责任对照

| 责任 | Java 基线（`/Users/shenmingjie/workSpace/LLMentor-teach/gogo-agent`） | Python 当前入口 |
| --- | --- | --- |
| 生成思考/工具进度 | `ProgressNotifierHook.onEvent` 的 Pre/PostCall、Pre/PostActing 及 thinking 通知 | `chat/trace.py` 的 `ExecutionTrace.on_reply → _record → _progress/emit` |
| 主子 Agent 统一观测 | 各 Agent 配置注册同一个 Hook | `chat/executor.py` 的主/Info/Manage builder 和 `planning/agent.py` 在构造时注入同一轮 trace middleware |
| 保持执行语义 | Hook 观察真实运行 | `on_reply` 对 `next_handler(**input_kwargs)` 的每个事件原样 `yield`；不能吞掉 `ReplyEndEvent`，SDK 依赖它结束回复 |
| SSE 交付 | `ChatSseNotifier` 向 emitter 发送 | `ExecutionTrace.stream` 并行消费原正文源与中间件队列，沿用 Java `thinking/progress` payload |
| 页面展示 | `AgentMessageBlock` 的 ThinkingBlock/ToolBlock；ProgressCard 提供计划列表 | 沿用同一组件，补实际父子归属、失败状态、键盘展开和历史 `extra.timeline` 映射 |
| 续聊 | 活跃 Agent 入口 | `InfoAgentContinuation.continue_turn(trace=...)`，只出现 InfoAgent，不虚构 GoGo 参与 |

Java 静态 `ProgressCard` 含 Python 尚未注册的 Agent；本次不把这些节点接入页面。当前用真实 `agent_start` 和 `parentAgentName` 显示正在执行的父子关系。Java 的工具参数/结果截断也未照搬；当前文本详情可滚动查看。

`async def on_reply` 是异步生成器，`async for` 消费 SDK 事件，`yield` 原样交回 SDK，类似能在处理前后观察的拦截器，但不等于 Java 同步回调。`asyncio.create_task` 建立正文生产任务，`asyncio.Queue(maxsize=128)` 通过 `await put` 施加背压，队列满时暂停生产；JSON 没有队列，只收集时间轴。`finally` 中取消并等待生产任务，让主/子模型的已有清理逻辑真正结束；它不是后台放任执行的线程。

思考按完整块交付再脱敏，防止密钥分散在多个 delta 时逐片漏出。因此页面在 block 结束后看到该段内容，不保证逐 token 展示思考。每次 `reply` 用 `reply_id` 区分，同一次 reply 内可有多轮 thinking 和工具；它们不会只按 Agent 名互相覆盖。
