# 015 L1/L2 遇到疑似多意图时弃权

L0、L1、L2 都只负责**单意图快判或弃权**；只有 L3 能返回有序的多个 `IntentItem` 并设置 `multi_intent=true`。L1 判 `ambiguous` 后，`IntentRecognizer` 跳过 L2，避免向量 Top-1 把整句压成一个类别。L2 自身在 Top-2 属于不同类别且分差 `<0.05` 时也会弃权。识别结果不等于执行动作；多意图执行留给 016。

## Java 基线与本次补充

Java L0 要求句长至少 10、出现强连接词且连接词位置至少为 4。Java L1 只在子句命中的类别横跨至少两个目标 Agent 时弃权；L2 仅按前两名分差判断。精确句 `查订单并规划下一程` 只有 9 个字，单字 `并` 不在 Java 切分器里，`查订单` 和 `规划下一程` 也都缺少原有规则词，因此 Java 会让它进入 L2。L2 是否误短路取决于实时分数，原逻辑没有结构性保证。

Python 在 [`IntentRuleMatcher`](../../src/gogo_agent/intent/rules.py)保留原有强连词和跨职责规则，补充一条保守判断：连接词或标点分开的子句，各自在开头附近出现**不同类型的动作词**，且至少一侧没有明确 L1 类别时，返回 `ambiguous` 并跳过 L2。这覆盖“泛称订单 + 下一程规划”等原规则盲区；同类动作补充和已识别的同职责请求仍可快速命中。它只判断是否需要慢路径，不替 L3 猜订单类型或编造第二个类别。

| 输入 | 快速层结果 | 后续 |
| --- | --- | --- |
| `查订单并规划下一程` | L1 `ambiguous`，不调用 L2 | L3 判断两个事项 |
| `我要申请出差并看政策` | L1 `ambiguous`，保留已知申请候选 | L3 判断“看政策”含义 |
| `查机票和酒店` | L1 `flight_search` | 单意图快速返回 |
| `帮我查机票，看看价格` | L1 `flight_search` | 同类查询动作快速返回 |
| `帮我查机票并不想申请` | L1 `flight_search` | 明确否定的“申请”不算第二个动作 |
| `修改一下，我的出差申请` | L1 `travel_modify` | 后半句是对象而非第二动作 |
| L2 不同类别 `.82 / .79` | L2 `ambiguous` | L3 判断两个事项 |

## 验收证据与边界

运行 `.venv/bin/python -m pytest -q tests/test_015_multi_intent.py tests/test_013_rules.py tests/test_014_vector.py tests/test_012_routing.py`。固定响应测试验证目标句的快速模式只尝试 L1，完整模式只再调用一次 L3，返回 `travel_order_query → itinerary_planning`，`primary_intent=itinerary_planning`、`multi_intent=true`；L2 近分差路径也返回相同有序结果。对照 Java 105 条分类正例仍为 105/105 一致，68 条 L2 种子仍全部由 L1 返回 `miss`。

2026-09-28 注入真实 Qdrant 匹配器并用当前真实聊天模型对 `查订单并规划下一程` 调用完整识别，实际 `attempted_layers=[rule,llm]`、`embedding_calls=0`、`intents=[travel_order_query,itinerary_planning]`、`primary_intent=itinerary_planning`、`multi_intent=true`。这证明本次输入在当前模型下达到目标；模型未来输出仍受其语义判断影响。未覆盖的隐含复合表述仍可能进入 L2/L3，快速层不保证穷尽识别所有复合句。

已知的旧规则边界：`帮我查机票并不要预订` 中的否定“预订”仍会被 L1 预订关键词命中，不能据本步声称所有否定句已正确分类；此类误路由按 018 的回归语料修复。HTTP 流水线接入见 [017 记录](016-017-执行与流水线.md)。
