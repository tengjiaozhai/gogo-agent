`async def` 类似返回 Future 的方法，但调用它仅创建 coroutine，直到 `await` 或 `asyncio.run` 才推进。脚本的 `asyncio.run(main())` 建立事件循环；调用栈是 `main→选定case→transform→on_model_call→await capture`。正式 Agent 由 SDK 的 `on_model_call` 链调用中间件。

`next_handler` 是 SDK 传入的“下一步”函数，类似拦截器链的 continuation；它不是新线程。`deepcopy` 后才改消息块，防止与 AgentState 共用对象。`preferences=lambda: ...` 是闭包：保留可信 RequestContext，每次执行重新查库；不会在 Agent 创建时把偏好冻结一整轮。

`redis.Redis` 客户端对应连接池与命令调用；HSET/HDEL 是单条原子命令，无需显式事务。`TemporaryDirectory` 已不再用于偏好演示。用户会话不等于存储连接；`session_reference` 也不能替代认证。`Literal`/Pydantic 校验类似枚举与 Bean Validation，但 Python 类型注解本身不会执行校验。

## 5. 自己预测并解释

1. **把预算 1000 改成 2000 并撤回授权后，压缩会不会恢复旧授权？**

   运行 `--case compress`。两条用户原文完整按序保留，没有从旧文本提炼一份“事实摘要”。只有完全相同的只读回执被引用；确认令牌、写回执和失败不参与此折叠。后端的执行授权照常独立校验。

2. **把阈值改为 10，能否把只有唯一用户文本的长对话压短？**

   不能。本方案选择不丢用户文字；测试 `test_078_unique_user_facts_are_never_truncated_when_threshold_is_exceeded` 直接覆盖这个边界。它没有解决任意超长、全为独特文本的会话压缩，不能据此宣称拥有通用摘要记忆。

3. **审核失败后只改回复文字，再说“已修复”，计划能否通过？**

   不能。运行 `--case repair`，看内容版本与三份审核记录；没有真实 compute 不会产生新方案。不可修复分支到第 3 次 compute 前就失败；可修复分支必须把超标酒店替换为补搜所得候选，再算、再审。测试替身只负责主观评估，客观金额/政策/时间校验是真实代码。

4. **Alice 的 plan_id 交给 Bob 能读出完整候选吗？恰好 24 小时呢？**

   运行 `--case reference`：Bob 为 PLAN_NOT_FOUND；Alice 过期时触发原始候选和方案的惰性清理，需重新搜索/计算/审核。过期清理不是后台定时任务；从未再访问的旧行不会自动物理删除。

5. **用户把偏好从高铁改为飞机，或撤回后，新会话会读到旧值吗？**

   运行 `--case memory`。同用户同分类替换原值，撤回后该条被删除。正式聊天每次聊天 Agent 模型调用重新读取有效偏好。注意：这不删除旧聊天原文；用户再次打开旧历史仍可看到当时说过的话。Prompt 要求本轮修正优先，模型是否遵循该要求需真实评测，工具授权不依赖偏好。

6. **固定路由集 8/8 是否意味着模型识别与选工具准确率 100%？**

   不是。运行 `--case routes`，在 `_build_agent` 前看 prepared：它由 fixture 注入。此实验检验“给定有效意图后只暴露允许工具”。识别器的已有回归另在意图测试中；真实模型选择质量待单独评测。

| 非法分类、空文本、请求中额外塞 `user_id` | 422；身份始终由登录 Token 解析 |

分类仅接受 `transport/hotel/schedule/other`。权威存储为 Redis Hash，键 `gogo:pref:{user_id}`，连接来自 `GOGO_REDIS_*`；测试与离线演示设 `GOGO_PREFERENCE_STORE=memory` 使用进程内后端。Redis 不可用时 PUT/GET/DELETE 返回 503，模型输入侧本轮跳过偏好并记录告警。它没有自动迁移旧的本机 SQLite 或共享 MariaDB，也未接前端偏好页。模型不提供 record_to_memory 写工具，聊天里的“以后都……”不会自动写库；需要用户使用已认证 API 显式保存。
