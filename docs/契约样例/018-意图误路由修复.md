# 018 基于回归语料修复意图误路由

## 输入证据与修复范围

固定语料见 [`018-意图回归语料.json`](018-意图回归语料.json)：14 条案例逐条保存原句、历史、来源、修复前表现和期望分支/改写/意图。它覆盖 Java 018 的三亚出差案例、Python 015–017 真实发现的否定预订和短追问误命中，以及原本正确的预订、航班、审批向量和多意图案例。不能用一条“意图准确率”代替这些不同错误边界。

| 问题 | 修复前实际结果 | 修复后实际结果 |
| --- | --- | --- |
| `帮我查机票并不要预订` | L1 `ambiguous`，多走慢路径 | L1 `flight_search` |
| `帮我查机票不要预订这个` | L1 `booking` | L1 `flight_search` |
| `不要订机票，只查火车` | L1 `flight_search` | L1 `train_search` |
| `明天去上海呢？`，前文是北京到杭州两天行程 | L2 `flight_search≈0.763`，跳过改写 | 先改写为 `2026年9月29日`从北京去上海的两天规划，L1 `itinerary_planning` |
| `明天去上海呢？`，无历史 | L2 `flight_search` | `needs_context`，请求补充动作或上一轮对象 |
| 三亚展会新出差，前文“帮我处理这次出差” | 改写丢掉“处理”，L3 `itinerary_planning` | 改写保留“处理这次出差”，L3 `travel_application` |
| `帮我写一个Python快速排序函数` | L3 `general_info` | L3 `unknown` |

### 为什么这样改

1. [`IntentRuleMatcher`](../../src/gogo_agent/intent/rules.py)在匹配前排除**明确否定的动作子句**。否定不等于待执行的“预订/取消”；若整句只剩否定动作，L1 弃权给 L3。若还有肯定查询，按保留的肯定句匹配。`不能不查机票` 这类双重否定会保守弃权，避免删掉肯定动作后高置信误命中；当前只覆盖代码列出的词形，不声称理解所有复杂否定结构。
2. [`IntentPipelineService`](../../src/gogo_agent/intent/pipeline.py)对带指代、缺少明确动作的短追问增加一个 018 例外：先结合历史改写，不让原句 L2 的近邻分数抢先定类；无历史直接请求补充。守卫仍让 `帮我预订这个航班` 和 `我交上去那个流程现在走到哪一步了` 走原有快路径；`明天去上海的航班呢？` 虽有领域名词，也属于省略动作的追问，先改写。没有整体调低 `0.75` 阈值。
3. [`QueryRewriter` 与 L3 提示](../../src/gogo_agent/intent/service.py)明确继承历史中的笼统办理动作，不把“处理这次出差”润色为“安排行程”；改写结果若丢失当前显式动作、减少同类动作次数，或丢失上一轮待办理的出差动作，直接报 `ModelOutputError`。例如 `查询航班并申请出差` 改成仅 `申请出差` 会失败。L3 将有时间、目的地、事由的新差旅办理归为 `travel_application`，把与差旅无关的编程、写作等请求归为 `unknown`。没有真实业务写入。

## 运行和验收

```bash
.venv/bin/python scripts/evaluate_018_intents.py
.venv/bin/python scripts/evaluate_018_intents.py --case sanya_new_trip
.venv/bin/python -m pytest -q tests/test_018_intent_regression.py tests/test_013_rules.py tests/test_014_vector.py tests/test_016_017_pipeline.py
```

[`evaluate_018_intents.py`](../../scripts/evaluate_018_intents.py)使用当前 `.env` 的真实聊天模型、embedding 和 Qdrant，按独立会话打印每条的“之前 / 改写 / 现在 / 差异”。2026-09-28 实跑 **14/14** 通过；另对照 Java 测试中的 105 条 L1 分类正例为 **105/105**，68 条意图种子仍全部是 L1 `miss`。这些 Java/种子对照是独立检查，不由上述真实模型脚本运行。固定测试隔离模型，验证否定规则、上下文守卫、正确快路径及错误改写被拒绝；真实模型语义结果仍可能随模型配置变化，运行脚本可直接复查。

016–017 的[断点 demo](../../scripts/demo_016_017_pipeline.py)仍能展示 L0、L1、L2、L3 和改写分支；其 `rewrite` 案例现在先由 018 指代守卫放行到改写，快筛 `attempted_layers=[]`，这正是避免原句 L2 误命中的显式分支。
