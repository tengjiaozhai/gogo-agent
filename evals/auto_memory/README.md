# 自动记忆评测（evals/auto_memory）

本目录评测长期记忆 P2 设计中的改口词守卫。设计依据见
[长期记忆整理机制-调研与实施方案-P0至P4.md](../../docs/research/长期记忆整理机制-调研与实施方案-P0至P4.md) §五 P2。

## 文件

| 文件 | 作用 | 是否调用模型 |
| --- | --- | --- |
| `cases/cue_guard.jsonl` | 改口词守卫标注集，37 条，由作者起草，未经复核 | — |
| `run_cue_guard.py` | 规则层：只测关键词判定的漏判率与误判率，直接导入生产模块 `gogo_agent.context.cue_guard` | 否，纯标准库 |

运行（任意目录均可，无需 `.venv`）：

```bash
python3 evals/auto_memory/run_cue_guard.py
```

脚本用 `sys.path.insert` 指向 `src/`，因此测的是生产代码里的同一份词表与判定函数，不是评测副本。脚本不读写 ReMe，不写 121，不修改任何生产数据。

## 标注规则

标签是**相对于 `existing`（现有有效条目）**定义的，即“这句话应不应该替换这条旧记忆”：

- `replace`：用户本轮明确表示，以后或从此以新内容为准，应允许替换 `existing`。
- `keep`：不应替换 `existing`。包括重复或确认、一次性（“这次”“这一趟”）、假设、疑问、否定、不同主题或属性、尚未决定。
- `ambiguous`：标注者无法判断是否为长期改变。不计入主指标，单独报告。

`scope` 字段：

- `same_turn`：守卫的判定输入就是 `utterance`，计入主指标。
- `cross_turn`：改口发生在上一轮（`previous_utterance`）。当前守卫只看本轮，这类样例单独报告，不计入主指标。`note` 写明前提。

样例类别（`category`）：

- `replace_with_term` / `multi_sentence_replace`：含词表词的改口，应被守卫放行。
- `replace_without_term`：明确改口但不含词表词，应被漏判。用来衡量词表覆盖。
- `keep_*`：不应替换。其中 `keep_*_with_term` 是误判高发项，用来衡量词表精度。
- `ambiguous_*`、`cross_turn_*`：不计入主指标。

## 指标

- **漏判率** = 应替换（same_turn）中守卫未放行的比例。漏判意味着旧条目残留。
- **误判率** = 不应替换（same_turn）中守卫放行的比例。误判意味着旧条目被错误替换。
- 同时输出分类别结果、词项诊断（每个词在两类句子中各出现几次）和明细，便于定位原因。

## 局限（读结果前必读）

1. **样例以困难情形为主，汇总率不是线上估计。** 比例取决于样例构成。比较设计时应看分类别结果；推断线上比例需要真实对话采样。
2. **标注由作者起草，未经第二人复核。** 请逐条检查标签，尤其是 `ambiguous` 与 `cross_turn` 的前提。
3. **守卫只看关键词，不看主题。** 主题是否匹配只能由模型判断加 id 校验，规则层测不到。
4. **不测模型输出。** 动作一致率、`max_tokens=400` 是否截断，属于模型层，尚未实现。
5. **基线词表未调参。** 生产模块 `cue_guard.CUE_TERMS` 固定使用设计文档的四个词，评测不单独改表。扩展词表前，应先划出未用于调参的样例做验证，否则是在同一批数据上过拟合。
6. **守卫不是注入防御。** 样例不覆盖提示注入场景。

## 修改标注

- 每条的 `id` 必须唯一；`cross_turn` 必须有 `previous_utterance`。`load_cases` 会校验这些约束，违反时直接报错。
- 修改标签后重新运行即可。提交时在说明里写明标注变更的原因。
