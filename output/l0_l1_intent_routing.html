🍜 5岁小朋友都能懂的比喻：牛肉面馆的“退单”惨剧

💡 想象你走进一家全自动牛肉面馆：

你站在自动点餐机（L1规则匹配）前喊了一句：“帮我【退掉】昨天的【红烧牛肉面】！”

❌ 没有设置“退/取消”一票否决权

点餐机是笨机器，它在句子里只认出了【牛肉面】！

灾难发生：点餐机高兴地喊：“好嘞！给您重新下一单红烧牛肉面，请付款 30 元！”
👉 你想退面，它反而强行又给你点了一碗面！

✅ 设置了“退/取消”一票否决权

点餐机虽然看到了【牛肉面】，但屏幕红灯狂闪：“警报！顾客说了【退掉】！”

安全自保：点餐机直接锁屏弃权：“这涉及退钱和撤单，我不敢乱动，请转人工服务台（L3大模型/经理）处理！”
👉 一票否决保平安，绝不把破坏性操作办反！

🛑 为什么“取消”在系统中必须拥有一票否决权？

在企业差旅系统中，“取消”是具有极高破坏性的终结动作。用户说取消时，句子里一定会带着名词宾语：

“取消我的【出差单】”
名词是“出差单”，若没否决权，会被【订单查询】误截胡。
“帮我把【机票】退了”
名词是“机票”，若没否决权，会被【航班搜索】拉去搜机票。
“取消下周的【行程规划】”
名词是“行程规划”，若没否决权，会被【规划助手】重新做行程。
核心法则： “取消”动作词一旦出现，普通名词查询规则必须立即全员噤声（一票否决），让位给专门的取消代理或交给大模型研判！

⚙️ L0 与 L1 的分工流水线

L0 哨兵
强连接词快速安检（红绿灯）
检查是否出现 然后、接着、顺便、完了再、外加。
目的：如果一句话包含多件事，单条规则必定会以偏概全。L0 看到强连接词立即主动弃权（AMBIGUOUS），直接护送进复合意图管线。
L1 规则
高精优先级关键词 + 负向排除词库
按严格优先级遍历意图：GREETING → REIMBURSEMENT → TRAVEL_CANCEL → TRAVEL_MODIFY → TRAVEL_ORDER_QUERY → ...
原则：宁可弃权（MISS）漏给后置层，也绝不抢答误判！
L2 向量
语义余弦相似度匹配（近义泛化）
当 L1 弃权时，通过 Qdrant / Dense Vector 匹配历史标准语料，支持口语化变形。
L3 大模型
LLM 终极推理兜底（深度理解）
处理复杂多意图、隐式否定、情绪表达与罕见句式，做最终仲裁。

🛠️ 彻底修复“路由不准确”的 4 级方案

为什么“帮我取消上次的出差单”在 L1 没有直接命中 TRAVEL_CANCEL，而是被排除词逼得弃权给 L2/L3？如何根治？

方案 1（L1 规则层）：拓宽 TRAVEL_CANCEL 的正向正则捕获范围（治本秒判）

原规则太死板（只认“取消出差”，中间插了“上次的”、末尾带了“单”就瞎了）：

- r"(取消出差|取消差旅|取消审批|取消我的(差旅|出差)|...)" + r"(取消.*(出差|差旅|审批)(单|申请|记录)?|撤回.*(差旅|出差|审批)?(申请|单)?|这次不去了?|不出差了)"

✨ 效果：让“帮我取消上次的出差单”在第 5 位直接 100% 秒判为取消，耗时 0 毫秒！

方案 2（L1 排除词层）：规范统一“一票否决动词表”

避免每个规则手工写排除词导致遗漏。将 {"提交", "取消", "修改", "报销", "规划"} 提取为动作动词常量池，在所有查询类规则（机票查询、火车查询、单据查询）中统一装配，杜绝名词截胡。

方案 3（L2 向量层）：扩充典型真实测试语料到种子库

在 intent_seeds.json 中为 TRAVEL_CANCEL 补充 5~10 条带修饰语的真实口语，如“帮我取消上次出差单”、“撤销上一笔出差”，确保即使 L1 弃权，L2 也能在 5ms 内高分命中。

方案 4（测试工程护栏）：TDD 增加端到端消歧回归用例

在 tests/test_013_rules.py 中加入对抗性测试用例集：验证“动词是取消、名词是查单”的复合句，确保路由准确率保持 100%。
